# skywire cli hv input

[← skywire cli hv](../README.md)

Dispatch TRUSTED pointer input into a running Chromium/Brave.

Unlike a synthetic event built with "hv eval" (new MouseEvent + dispatchEvent),
these go in at the browser level, so they are routed — and swallowed by — the
same things that route and swallow a real pointer. That is what makes it
possible to test that a click inside an <iframe> raises its window, or that a
drag whose path crosses a frame still ends.

Coordinates are viewport CSS pixels, the space getBoundingClientRect reports,
so read a target's box with "hv eval" and aim at it.

  skywire cli hv input ws://localhost:9222/devtools/page/ABC --click 400,300
  skywire cli hv input ws://localhost:9222/devtools/page/ABC --drag 120,40:900,500
  skywire cli hv input --port 9222 --move 10,10

The real pointer stays live during a gesture. If it moves between a scripted
press and release the page sees a drag this command did not send, and the
outcome is not that of the scripted input; the command says so on stderr
(--strict makes it fail instead). Keep the mouse off the browser while a
gesture runs.

## Usage

```
skywire cli hv input [webSocketDebuggerUrl]
```

## Flags

```
      --click string    click at X,Y (viewport CSS pixels)
      --drag string     press at X1,Y1, move to X2,Y2, release — as X1,Y1:X2,Y2
      --move string     move the pointer to X,Y without pressing
      --port string     debug port of the running browser, when no webSocketDebuggerUrl is given (default "9222")
      --settle-ms int   pause between the events of a drag, so the page can run its handlers between them (default 16)
      --steps int       intermediate moves in a drag; the path is what crosses a frame, so more steps is a more faithful drag (default 12)
      --strict          fail, rather than warn, when the real pointer moved during the gesture — the page then saw a drag no test asked for, and the outcome is not that of the scripted input
      --timeout int     seconds to wait for the browser to acknowledge (default 30)
```
