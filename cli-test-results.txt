## Summary
================================================================================

### Overall Assessment
The CLI is well-structured and functional. Most commands work correctly with
clear output. The command tree is logically organized with good grouping.

### Bugs / Issues Found

1. **config gen -o /dev/null fails** — "Insufficient permissions to write to
   the specified path". The permission check appears overly strict (stat-based
   rather than actual write attempt).

2. **svc health --json prints BOTH table and JSON** — The --json flag should
   suppress the human-readable table, not append JSON after it.

3. **svc health --json is undocumented** — Not shown in --help output, but
   the flag works.

4. **mdisc servers --stats is not a valid flag** — --stats exists on parent
   `mdisc` but not on `mdisc servers`. Inconsistent with user expectation.

5. **tp all --stats is not a valid flag** — No --stats flag. Use `tp net-stats`
   instead, but this is not obvious.

6. **mdisc entry (no args) exits 0** — Should exit 1 or require an arg. Currently
   just shows help and exits cleanly, giving no indication that the command
   did nothing.

### Missing Features / Usability Issues

7. **visor halt has no confirmation prompt** — Destructive action with no
   --yes/--force flag. Shut down a running visor without warning.

8. **config gen-keys output has no labels** — Just two lines of hex. Adding
   "PK:" and "SK:" prefixes or a --json flag would improve usability.

9. **tp disc rejects positional pk arg** — Must use --pk flag. Error message
   "must specify either transport id or public key" doesn't guide the user
   to the correct flag syntax.

10. **reward rules outputs ~37KB of ANSI art logo** — Impractical in scripts
    or log files. Needs --no-logo or --text-only flag.

11. **Noisy RPC error/debug log lines** — Commands like `svc health` and
    `mdisc servers` print ERROR + DEBUG lines about RPC connection even when
    the fallback works fine. These should be suppressed or reduced to TRACE.

### Typos

12. **survey --help**: "optionl" should be "optional" in the --config flag
    description.

### Consistency Issues

13. **--json flag availability is inconsistent**: Some commands have it
    (svc health, tp tpd-stats, sd, tp v, proxy list, vpn list), survey
    outputs JSON by default, and many commands don't have it at all.

14. **--stats flag availability is inconsistent**: Available on pv, ut, mdisc,
    tp tree, tp v, but not on mdisc servers or tp all.

15. **Error message style varies**: Some use FATAL log format, some use bare
    "Failed to execute command:", some use custom messages.

### Commands That Work Well

- `visor info` — excellent comprehensive summary
- `svc health` — clear table format (minus the log noise)
- `tp net-stats` — clean aggregate stats
- `tp tpd-stats --json` — well-structured JSON output
- `tp metrics` — clear bandwidth table
- `dmsg sessions` — nice tree view
- `util jq` — works as expected
- `config gen --stdout` + `config parse` — good workflow
- `ut --stats` / `pv --stats` — quick counts

### Test Statistics
- Commands tested: ~60
- Passed: ~52
- Issues found: 15 (6 bugs, 5 usability, 1 typo, 3 consistency)
