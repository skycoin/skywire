# Gate G3 — M3 SkyChat (independent review)
Reviewer: fresh session 2026-09-30   Author: M3 author (mrpalide)
SHA: fa56b5302 (M3 = 2d1cafed5)   PRs: https://github.com/mrpalide/skywire/pull/1   Date: 2026-10-01
Verdict: FAIL

The chat itself works both ways between a fresh Simulator and the Android
emulator. The QR bridge decodes a saved image. History survives a
force-quit. The hub stream reconnects after a core restart. ATS and the web
view settings are as tight as required. **The gate fails on its background
leg:** backgrounded with the home gesture, the app is suspended by iOS 5 s
later, so its in-process core stops. The peer sees it offline and no
notification is shown until the user reopens the app. Separately, the
`iOS app` CI lane has been red since M3's own commit, on the QrBridge unit
test that is part of the exit evidence.

The reviewer was asked to keep the run short. The steps marked "not run"
below were skipped for time, not because they failed. The re-review must
cover them.

## Criteria
- [ ] **"the conversation above from scratch (fresh Simulator, new identity)"**: partly passed.
  Erased iPhone 18 Pro, new key 0244c932…c453. Text both ways over Skynet:

  prompt at 23:39:02 on the just-erased device. Allowed.
- [ ] **"background the app, send from the emulator, see the notification, tap it, land in the chat"**: **FAILED.**
  After the home gesture, RunningBoard set the app's role to Background at
  23:53:05 and reported "Suspending task" / `running-suspended` at 23:53:10.
  The emulator showed the iOS peer "offline", and its message sat at
  "Establishing connection … 1 message waiting". No notification was posted
  while the app was in the background (no `posted a notification` in the
  `notify` log), so there was nothing to tap. The message arrived at 00:01,
  only after the app was reopened; the hub stream then logged "The request
  timed out", reopened at 00:00:30, and the page showed the message. The
  app has no `beginBackgroundTask`, `UIBackgroundModes` or `BGTaskScheduler`,
  so the playbook's proxy ("in the background but still running") does not
  exist on this build: a backgrounded app is suspended within seconds. The
  author's notes already list this leg as "Not proven by a script". Bench load:
  the emulator's qemu ran at ~495% CPU (8 cores) during the run, but
  suspension is RunningBoard's policy for an app that asks for no background
  time, and happens regardless of CPU load.

## Non-blocking notes
1. `NotificationBridge.readHub` awaits `center.notificationSettings()` after the stream opens, only to log the permission; on the fresh device that call
   waited until the permission prompt was shown (23:36:35 → 23:39:03), and no
   events were read in that time. The hub keeps no backlog.
2. `pollUnread` keeps its `SkychatClient` for the bridge's lifetime; after a skychat restart that rewrites the password file it will keep the old secret until the core reconnects. Not observed; worth checking.
3. CodeQL's 18 "new" alerts are all in pre-existing Go code outside M3's files (`pkg/pty`, `pkg/visor/api_browse.go`, CLI quoting, cxo paths…). None is in `hypervisor_handlers_notify.go` or the skychat page.
4. Bench: the emulator's qemu held ~495% CPU, which made the Simulator's screenshots lag and dropped some first taps. That did not change any result above.
5. The emulator's skychat already had conversations from earlier gates. It is not a fresh identity (the gate asks for that on the Simulator only).
6. `simctl addmedia` of two PNGs put both in Photos; the picker preselected the QR, whose decode is what ran.
