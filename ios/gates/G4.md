## Non-blocking notes
1. **A core restart drops a connected SkySOCKS.** This covers Home >
   Restart core, the Fleet switch and applying the grant.
   - After each, SkySOCKS reads Disconnected, offers Reconnect, and nothing
     listens on 1080 (`skysocks-client` stays `auto_start=false`).
   - 4.8 asks only for the core to come back connected, so this is not a
     failure.
   - But a user who switches Fleet on loses their proxy silently, and the
     confirmation only says the core restarts. Worth a decision: restore it,
     or say so in the dialog.
2. **Version rows are hyphenated inside the commit hash.**
   - Home's Version (`v0.0.0-76bbeb063-76bbeb0639e6 · ios_arm64`) and
     Fleet's Version wrap as `…-76bbe-` / `b0639e6`. The accessibility label
     has no hyphen, so iOS adds it.
   - Same class as M4's key fix (`Format.breakable`), but these rows were
     not passed through it. Seen in en and es.
   - Not a key, so not the known finding, but it misreads the commit.
3. **SkySOCKS "Transferred" stayed `↑ 0 B ↓ 0 B`** while traffic flowed
   (two ipify requests, then ~85 KB through my own server). The row takes
   `.first` of `/apps/skysocks-client/connections`. Android's
   implementation-report says `bandwidth_sent`/`_received` do move, so
   either the visor reports 0 for this connection or the first entry is not
   the live one. Not traced: the visor API is behind the app's Keychain
   password.

     15:39:53 the row was back to online with the pre-restart uptime

     row says online while the visor is down.
